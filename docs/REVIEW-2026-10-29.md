1. **真 bug 与违约点**（功能不生效、战斗中状态闪灭、与 AGENTS 约定冲突）；

3. **大量死代码和重复**（估计可删 500+ 行）；
4. **结构性债务**（超大配置函数、各模块各自造的 OnUpdate 与 Watch 轮询、四套单位框各写一遍生命周期骨架、靠 `M.xxx` 快照的文件拆分、皮肤帧名两处维护）。

## 四、基础设施与重复

### 4.1 重复的轮询 / 观察机制
- 全仓约 52 处 `SetScript("OnUpdate")`，8 个以上各带自己的累加器和节流（`Widget.lua:59/106/146/848/1075`、`Skin.lua:451/591/927`、`Cooldown.lua:385`、`ActionBars` 多处）。建议合并为一个调度器。
- `Widget:HoverWatch` **一个框只能挂一个回调**（`Widget.lua:89-97`），后来的覆盖前面的。`Skin.lua:410-411` 先调 `HoverHighlight` 再调 `ControlState`，前者的 enter/leave 被静默顶掉。`PollWatch` 早已改成多回调，HoverWatch 应同样改。
- 三个 Watch 表（`hoverWatch` / `showWatch` / `pollWatch`）都是强引用，**没有注销接口**（`Widget.lua:35/101/128`）。
- `PollWatch` 的回调内 `pcall` 静默吞错，应走 `EventBus` 报告。
- 挂在 `UIParent` 上的常驻轮询：`System.lua:279`、`Forever.lua:162`、`Nameplates.lua:177`、`Cooldown.lua:615`、`Bags.lua:530`，每 0.2 秒全跑。`Forever.lua:162` 的 `repaint` 经 `Debounce`，每秒约 5 次闭包分配（注释写"每 1 秒"是错的）。
- `Cooldown.lua:615` 的 PollWatch 超过 60 次后只 return，回调永不注销。

### 4.2 `ns.Mark` 的包装重复
- `local Mark = function(o,k,v) return ns:Mark(o,k,v) end` 在约 20 个文件里各抄一份。
- Utils 层反向依赖 Core（`ns:Mark`），依赖方向倒置。
- 建议：把无 self 的 `Mark/Marked` 作为纯函数挪到 `Utils/Secrets.lua` 或新建 `Utils/Guard.lua`，Core 只做转发。

### 4.3 热路径开销（非单位框部分）
- `Media:Mult`（`Media.lua:101-136`）每次调用 3 次 `pcall` + `tonumber`，被 `SnapUnit`、`Widget:Size`、`Cursor.lua:96`（逐帧）调用。应缓存。
- `Widget.lua:376-416` `FitText` 每次新建闭包 `apply`，无条件 `SetFont`。
- `Widget.lua:523-571`、`:675-725` `SetBorderState` 每个脉冲帧走完整 `Refresh`，内有临时表；`ROUND_SLICE` 与 `ROUND_EDGES.slice` 是两个数据源。
- `Skin.lua:644` `ScanScrollArrows` 每个帧新建 pcall 闭包；`EnumerateFrames` 全量扫描，跑 4 次（1/3/6/10 秒）。
- `Skin.lua:585-600` `arrowDriver` 每 0.3 秒对暴雪 region 调 `SetAlpha(0)`，不看是否可见（未提交修改）。
- `Skin.lua:921-937` `cropDriver` 每 0.5 秒对所有裁剪过的图标（包括我们自建的）重压 texcoord。
- `Bags.lua:642` `GUARD_INTERVAL = 0.05`，每拍 `BlizzardBagFrames()` 新建 table 并 `CollectTree` 约 15 个暴雪帧。
- `QuestTracker.lua:433-441` 每 1 秒递归整棵暴雪追踪子树。
- `Tooltip.lua:428`、`Pins.lua:150`：模块关闭后驱动仍空转。
- `ActionBars.lua:557-587`、`391-402`、`443-447`：对我们**自建**的 FontString/Texture 的 SetText/Show/Hide 包了约 12 个 pcall。
- `ActionBars.lua:551-592` `UpdateAll` 每格约 15 次 pcall，无脏检查；`RefreshRings`（:1683）每次重涂 192 个贴图。
- `Cooldown.lua:385` 驱动每 0.05 秒遍历全部 attached；空闲格仍每 0.5 秒跑 `Options()`、`GetCooldownTimes`、`HandBack`。

### 4.4 EventBus / 生命周期
- `EventBus.lua:143`：非单位事件 `Unregister` 清空后不 `UnregisterEvent`；`:166` 的 `UnregisterAll` 同样不退引擎注册。
- `EventBus.lua:135`：同一事件混用 `RegisterEvent` 与 `RegisterUnitEvent`，会互相过滤。
- `Skin.lua:76` `Skin.tinters`、`Skin.added` 只增不减，闭包强引用暴雪框。
- 生命周期不对称：`XP.lua`（Hide 后不还原、ShowWatch 不注销）、`Buttons.lua:245`、`Skin.lua` 的 `ScrollArrowButton`（`SetAlpha(0)` 没有 `Record`，关掉 Skins 后暴雪箭头仍被压）、`Bags.lua:845-852` 的 `BANKFRAME_OPENED`（没有 `IsModuleEnabled` 判断）。
- 对称良好：`Toast`、`Tooltip`、`CombatText`（CVar 存档并还原）、`QuestTracker`。

### 4.5 配置与默认值
- `Core.lua:550-556` `IsModuleEnabled` 用 `DEFAULTS.modules[name] ~= false` 兜底。`DEFAULTS.modules`（:15-28）缺 Cursor、Toast、Durability、CombatText、BossFrames；`MODULE_ORDER`（:29-33）缺 GroupFrames、BossFrames。
- 默认值在面板里重复写死（`SimpleConfig.lua` :726-730、:851、:922），getter 有 7 种写法。键名拼错会静默失败：`NameplateCheckbox` 用 `~= false`（:249），拼错的键读到 nil 会显示为"已勾选"。
- `Toggle`（:1525-1541）打开面板时只刷新模块复选框与下拉框，普通复选框不刷新。
- `Core.lua:304-373` `Migrate`：没有 pcall；新库 `schema` 为 nil，会把 v2–v8 全部跑一遍；v2/v3 重复。
- `Core.lua:818` 格式串 `"%dxxd"` 笔误。`Core.lua:11` `ns.version` 是 0.11.0，toc 是 0.12.0。`Core.lua:780` `PrintScale` 绕过 `ReadCVar`。

### 4.6 皮肤层

- `Trade.lua` 邮件按钮在 :55-62 与 :150-154 重复。
- `Social.lua:33-41` 对 `FriendsFrame` 每个子 Frame 逐个 `HookShow`，每个都成为永久 `ShowWatch` 条目；`Skins.lua:296` 同一帧只允许登记一次，后来的回调被静默丢弃。
- `Quest.lua` 的 `BrightenTree` 无 pcall，遇到 forbidden 对象会中断递归。`Quest.lua:206` 的模块判断只判一次。
- `Skins:SetEnabled` 后 `ShowWatch` / `HoverWatch` / `HookShow` 无注销接口。

### 4.7 ActionBars 结构

- 拆分边界（子代理报）：Defs 1–325、Refresh 326–592、Button 419–774、Layout 776–854、Stance/Adopt 856–1069、CreateBar 1071–1228、Bindings 1546–1584、Events/Apply 1586–1896。
- `ADOPT_EVENTS`（13 个事件）全部指向 no-op 的 `AdoptAll`，应去掉。
